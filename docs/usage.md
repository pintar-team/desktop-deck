# Using Desktop Deck

Add a connection from the sidebar. The editor groups SSH and VNC separately, with advanced fields collapsed. An SSH endpoint alone creates a terminal connection; VNC alone provides a desktop; both provide SSH terminals and a tunneled desktop. Session Manager uses the SSH block and a pinned screen; its standard installation directory is hidden under Advanced. Existing SSH configuration, keys, ssh-agent and verified host keys are used. Resolve unknown/changed host keys through your normal SSH setup; the app never accepts them automatically. VNC passwords are stored in Keychain, not in profiles or source. Changing the SSH host or port clears an inherited host-key alias; enter an explicit alias under Advanced after selecting the new server if needed. Duplicating the same server preserves its verification alias.

Workspace tabs save their own set of connections, ordering, grid selection and focused desktop. A single workspace does not display a redundant tab. The same connection can appear in several workspaces without opening duplicate transports. Choose **Fit all** to fit every desktop into the window, or **2 × N / 3 × N / 4 × N / 5 × N** for fixed-column continuous grids. Tiles touch edge to edge, with names overlaid as shadowed text; the selected desktop has an accent border. Click a preview to control it; select **Overview** or use **Command-Shift-G** to return. One compact toolbar contains four view buttons: Overview, Desktop, Terminal and Split. The filmstrip and sidebar are independent toggles. The toolbar follows the selected connection’s accent. Its full-screen button and **Control-Command-F** enter native macOS full screen. **Command-Shift-I** toggles toolbar auto-hide; a persistent corner handle reveals the toolbar or toggles the sidebar. Previews always fit the complete framebuffer, independently of focus-mode zoom. Option-scroll or pinch zooms the focused desktop; Option-drag pans. Remote resolution changes are explicit. Drag tiles or sidebar rows to reorder the current workspace; other workspace orders stay independent. The connection menu offers **Duplicate connection** as an editable draft with a new ID and automatic color. Passwords and terminal sessions are not duplicated.

Import/export configuration from the workspace menu as versioned JSON containing profiles and grid presets. Passwords and terminal sessions are excluded. Import validates the complete document first, adds missing IDs, and preserves existing settings; explicit edits use the editor or MCP.

Each profile receives a stable automatic accent from a twelve-color palette, avoiding already assigned colors when possible. It is saved independently of workspace order. Change it quickly through the connection's **Accent color** menu, or choose any color in the connection editor. Returning to Automatic restores its saved automatic color.

For active SSH hosts, the sidebar and every preview show CPU and disk usage percentages with compact icons. Hover the sidebar values for OS, disk path, available/total space and sample time. The monitor shares one snapshot across profiles with the same configured SSH host, port and host-key alias. It polls every 30 seconds, runs only one bounded read-only SSH probe at a time and backs off on errors independently of VNC recovery. Linux uses `/proc/stat` counter deltas, macOS uses `top`, BSD uses `kern.cp_time`, and Unix disk space uses `df`; Windows uses built-in PowerShell/CIM when available. Disk usage is derived from space available to the account on `/` (Windows: the system drive), including reserved/shared-pool effects. Unsupported values show a dash; old samples dim after 90 seconds. Disable **Host CPU and disk · SSH** in the workspace menu. No metrics are persisted or exported.

Terminal-only previews fit the complete current viewport, preserving its rows and columns without resizing the live terminal. They refresh once per second. Names and metrics sit over soft dark gradients for contrast on light content.

Preview frame softening uses a 70 ms GPU blend with at most two textures and short-lived redraw timers; static views stop redrawing. It can be disabled in the view menu, and Reduce Motion disables it. The focused interactive screen always presents new pixels immediately. This is visual smoothing, not reconstructed motion or a claim of zero rendering cost.

Connection loss keeps the last framebuffer with a disconnected indicator and schedules exponential retries. Each attempt has a 30-second deadline covering SSH setup, VNC handshake and the first actual framebuffer. Six unsuccessful attempts stop with **Try again**; the counter resets after a connection remains established for 30 seconds. Waiting for network or a setup slot does not consume attempts. Authentication/host-key rejection requires attention immediately. **Reconnect now** restarts the budget; a manual disconnect cancels retries and interrupts pending protocol reads. Static connected desktops do not disconnect merely because no pixels changed. No input or command is replayed after recovery.

TurboVNC Session Manager is an optional capability: list and pin existing displays, or explicitly create a desktop. It uses the upstream `vncserver -sessionlist`, `-sessionstart` and `vncpasswd -o` interfaces through SSH. Its one-time VNC password uses VNC authentication within the verified SSH tunnel. The session picker remains usable during reconnect and offers the previous selected display. Selecting another display cancels the old attempt and clears its framebuffer. The initial server install directory is `/opt/TurboVNC`. Generic VNC endpoints work without Session Manager.

Each SSH profile has terminal tabs powered by SwiftTerm. Choose **Desktop**, **Terminal** (the whole work area), or **Split** with a draggable boundary. **Command-Shift-T** switches desktop/terminal. Switching views preserves terminal sessions and VNC connections. Selecting a connection, preview, view mode or terminal tab transfers keyboard focus to its active surface without a second click. Frame updates, recovery and MCP navigation do not repeatedly take focus from search or settings. Saving names, groups, colors or auto-connect settings also preserves live connections. Enabling Auto-connect immediately connects an idle profile and enables connection on future launches; disabling it leaves current sessions running. Changing VNC connection settings detaches its transport. Existing terminal tabs keep their original SSH binding; tabs from previous settings show their target. Connect opens or reconnects a terminal for the current settings without terminating older shells. Auto mode checks for tmux and uses a separate `desktop-deck` tmux socket and app-owned session names when present. Closing the app or detaching a persistent terminal preserves the remote shell; **End terminal** explicitly ends it. Without tmux, the app runs a plain SSH shell; after a lost connection, reconnecting starts a new shell. tmux is never installed automatically and cannot preserve sessions across server reboot or tmux-server termination.

The keyboard menu provides text clipboard transfer, paste, Alt+Tab, Ctrl+Alt+Delete and held modifiers. With a remote desktop focused, **Command-C** sends Ctrl+C and **Command-V** transfers the Mac text clipboard before sending Ctrl+V; terminal applications can use the menu's Ctrl+Shift+V paste. Remote clipboard changes update the Mac clipboard only while that interactive desktop owns keyboard focus in the active app. Disable receiving in the keyboard menu if desired. Other connected desktops keep separate clipboard snapshots and cannot overwrite the Mac clipboard. VNC text transfers are bounded to 1 MB. UTF-8 uses the server's Extended Clipboard capability; legacy endpoints support Latin-1 without silently corrupting unsupported characters. Brief toasts report explicit copy/paste operations without displaying clipboard contents. Unsolicited clipboard/primary-selection updates synchronize quietly. SwiftTerm retains native text selection and Mac copy/paste.


## Image paste and drop

Focus the input field in the remote chat first. Command-V accepts a screenshot/image from the Mac clipboard, and you can also drop an image file or a macOS screenshot thumbnail onto the focused desktop. Both actions paste into the existing remote input focus; dropping does not click remote controls. The receiving application must support image attachments. Paste does not press Enter or submit the chat.

This uses a separate SSH bridge for **Linux X11**, because the pinned VNC client/server clipboard path transfers text. It requires `xclip` and standard Linux utilities (`timeout`, `mktemp`, `cmp`) already available on the desktop host, existing SSH access, and an explicit selected X11 screen. The client installs nothing. Session Manager profiles work directly; direct tunneled profiles need an explicit display and a loopback VNC target on the SSH host. Gateways pointing to another desktop host are rejected.

Images are decoded locally and re-encoded as PNG without EXIF/GPS metadata. Image files and encoded PNG output are capped at 20 MB. Native TIFF clipboard data can be up to 168 MB before PNG conversion, so full Retina screenshots are accepted. Dimensions are capped at 16,384 pixels per axis and 40 million pixels in total. The background converter admits one image at a time. Each connection has at most one image transfer; cancel it from the keyboard menu while uploading. Private temporary files are removed on completion/cancellation, and the remote clipboard provider expires after 30 seconds. SSH operations have a 45-second deadline and never retry automatically.

Changing screens, losing input focus, another human action or another controller taking the input lease prevents a delayed automatic paste. Text clipboard synchronization does not replace a Mac image/file clipboard with an empty text notification. Image transfer is available through the human interface; the MCP clipboard tool remains text-only. VNC-only endpoints, Wayland, Windows and macOS remote image clipboards are not currently supported.

## Sidebar width

Drag the sidebar boundary anywhere along its height, including beside letterboxing or an empty workspace. Its hit area is wider than the visible line and shows the horizontal resize cursor. Width is constrained to 170–300 points; live dragging uses window coordinates without animation, and the saved width is written when the drag ends. The splitter also exposes accessibility increment/decrement actions.

In Fit mode, showing or widening the sidebar recomputes the available video canvas and keeps the complete remote desktop visible. This changes local scaling, not the server resolution. Explicit zoom and pan remain under your control. On an empty connecting screen, the connection action appears below its centered status.
